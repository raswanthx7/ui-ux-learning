# What is Design Thinking?

**Design Thinking** is a human-centered problem-solving process.

Instead of immediately finding a solution, designers first try to understand the user's problem.

Simply put,

> **Design Thinking means understanding the real problem before trying to solve it.**

---

## Simple Example – Tea Shop

Imagine you own a tea shop.

One day, fewer customers start coming.

You immediately think,

> "Maybe I should paint the shop."

or

> "Maybe I should give discounts."

But are those really the problem?

Maybe...

- Tea takes too long to prepare.
- There are not enough chairs.
- Customers don't like waiting.
- The shop is too crowded.

You don't know yet.

So first, you talk to customers and understand their problems.

Only then do you decide what to improve.

This is **Design Thinking**.

---

# Why Designers Use Design Thinking

Without Design Thinking, people often solve the wrong problem.

### Without Design Thinking

**Problem:**

Customers are not coming.

**Owner's Solution:**

Paint the tea shop.

**Result:**

Still no customers.

---

### With Design Thinking

The owner asks customers,

> "Why aren't you coming here?"

Customers reply,

> "The tea takes 20 minutes to prepare."

Now the real problem is clear.

The owner hires another tea maker.

Tea is served in 5 minutes.

Customers start coming back.

### Lesson

Design Thinking helps us solve the **real problem**, not the problem we assume.

# The Five Stages of Design Thinking

```
Empathize
     ↓
Define
     ↓
Ideate
     ↓
Prototype
     ↓
Test
```

Let's understand each stage using the tea shop example.

---

# 1. Empathize

## Meaning

Understand your users.

Don't guess.

Talk to them.

Ask questions.

Observe them.

### Tea Shop Example

The owner asks customers,

- Why don't you come here often?
- What problems do you face?

Customers say,

- Tea takes too long.
- There are no seats.
- The shop is crowded.

The owner only listens.

He doesn't solve anything yet.

### In UI/UX

Instead of customers, designers interview app users.

---

# 2. Define

## Meaning

Find the real problem.

After talking to many customers,

18 out of 20 people say,

> "Tea takes too long."

Now the owner knows the actual problem.

### Problem Statement

> Customers stop visiting because the waiting time is too long.

Now everyone is solving the correct problem.

---

# 3. Ideate

## Meaning

Think of many possible solutions.

Don't choose the first idea.

Brainstorm.

### Tea Shop Example

Possible ideas:

- Hire another tea maker.
- Prepare tea faster.
- Add a token system.
- Separate billing and tea preparation.
- Allow customers to pre-order.

All ideas are welcome.

Later, choose the best one.

---

# 4. Prototype

## Meaning

Build a simple version of your solution.

Don't spend a lot of money immediately.

Try a small experiment first.

### Tea Shop Example

Instead of buying expensive machines,

the owner simply starts using paper tokens.

```
Customer

↓

Gets Token

↓

Tea Prepared

↓

Token Number Called

↓

Customer Collects Tea
```

This simple token system is the prototype.

### In UI/UX

Instead of developing an app,

designers create clickable screens in Figma.

---

# 5. Test

## Meaning

Let users try your solution.

Observe them.

Collect feedback.

### Tea Shop Example

Customers use the new token system.

Some say,

✅ Waiting time is much better.

Some say,

❌ Token numbers are confusing.

Now the owner knows what needs improvement.

---

# Iterative Design

Design Thinking is **not a one-time process**.

Designers improve their solution again and again.

This is called **Iteration**.

```
Version 1

↓

Users Give Feedback

↓

Improve

↓

Version 2

↓

Users Test Again

↓

Improve Again

↓

Version 3
```

Every version becomes better than the previous one.

# Real-World Example – Swiggy

Imagine Swiggy's "Track Order" button was very small.

Many users couldn't find it.

Instead of assuming everything was fine,

the designers observed users.

### They discovered

Users were searching for the Track Order button.

### They defined the problem

The button is difficult to notice.

### They generated ideas

- Bigger button
- Better color
- Better position

### They created a prototype

A new app screen with a larger Track Order button.

### They tested it

Users found the button much faster.

Swiggy kept improving the design based on user feedback.

This is Design Thinking in action.

# Everyday Example

Imagine your friend says,

> "I'm always late to college."

Don't immediately say,

> "Buy a bike."

Instead,

### Empathize

Ask,

> "Why are you late?"

### Define

He says,

> "The bus arrives late every morning."

### Ideate

Think of different solutions.

- Leave earlier
- Use another bus
- Ride a bicycle
- Share a ride with a friend

### Prototype

Try leaving 20 minutes earlier for one week.

### Test

If it works,

great.

If not,

try another solution.

This is Design Thinking.

---

# Design Thinking vs Normal Thinking

| Normal Thinking | Design Thinking |
|-----------------|-----------------|
| Guess the problem | Understand the problem |
| One solution | Many possible solutions |
| Build first | Learn first |
| Test at the end | Test throughout the process |
| Focus on the product | Focus on the user |

---

# Key Takeaways

- Design Thinking is a human-centered way of solving problems.
- Always understand the user's problem before creating a solution.
- The five stages are:
  - Empathize
  - Define
  - Ideate
  - Prototype
  - Test
- Testing gives valuable feedback.
- Designers continuously improve their work through **iteration**.
- Great products are created by solving **real user problems**, not by making assumptions.

---

## Easy Way to Remember

| Stage | Easy Meaning |
|--------|--------------|
| **Empathize** | Understand the user |
| **Define** | Find the real problem |
| **Ideate** | Think of many solutions |
| **Prototype** | Make a simple version |
| **Test** | Let users try it and improve it |

### Remember This Line

> **Understand the problem → Think of solutions → Build a simple version → Test → Improve.**
