# Design Laws Cheat Sheet

| Design Law | Simple Meaning | UI/UX Example | UX Takeaway |
|------------|----------------|---------------|-------------|
| **Hick's Law** | More choices = More time to decide | Swiggy shows only popular food categories first instead of 100 categories | Reduce unnecessary options to make decisions faster. |
| **Fitts's Law** | Bigger and closer buttons are easier to tap | Large **Add to Cart** and **Place Order** buttons | Make important actions large and easy to reach. |
| **Jakob's Law** | Users expect familiar interfaces | Search at the top, bottom navigation, cart icon | Follow common design patterns users already know. |
| **Miller's Law** | People can only remember a limited amount of information at once | Checkout process is split into steps instead of showing everything | Avoid overwhelming users with too much information. |
| **Tesler's Law** | Complexity should be handled by the system, not the user | Swiggy calculates delivery time, taxes, and discounts automatically | Keep the interface simple while the system handles complexity. |
| **Doherty Threshold** | Fast feedback keeps users engaged | Loading animation appears immediately after tapping **Place Order** | Give instant feedback after every user action. |
| **Pareto Principle (80/20 Rule)** | 80% of users use only 20% of the features | Search, Order, Track Delivery are the most-used features | Prioritize designing the most frequently used features. |
| **Von Restorff Effect** | Different items grab attention | Bright orange **Place Order** button | Highlight the most important action using contrast. |
| **Peak-End Rule** | Users remember the most emotional moment and the ending | Order confirmation screen with success animation | Create memorable key moments and satisfying endings. |
| **Serial Position Effect** | Users remember the first and last items better | Home and Profile in bottom navigation | Place important items at the beginning or end of lists. |
| **Law of Proximity** | Items close together are seen as related | Product name, price, and rating are grouped together | Group related information using spacing. |
| **Law of Similarity** | Similar-looking elements are perceived as belonging together | Category cards use the same shape and style | Keep similar elements visually consistent. |
| **Law of Common Region** | Items inside the same container are seen as one group | Offers displayed inside one card | Use cards and containers to group related content. |
| **Law of Continuity** | The eye naturally follows smooth paths | Vertical scrolling list of restaurants | Arrange content to guide the user's eyes naturally. |
| **Law of Closure** | The brain completes incomplete shapes | Cards with subtle shadows instead of heavy borders | Users can understand layouts without every boundary being drawn. |
| **Law of Prägnanz (Simplicity)** | People prefer simple, organized layouts | Clean home screen with minimal elements | Remove unnecessary visual clutter and keep interfaces simple. |

# Applying Design Laws in a Real Interface

| Screen | Design Law Applied | Example |
|---------|--------------------|---------|
| Home Screen | Hick's Law | Show only essential actions like Search, Categories, and Today's Offers. |
| Product Card | Proximity | Keep product image, name, rating, and price close together. |
| Add to Cart | Fitts's Law | Large, easy-to-tap **Add** button. |
| Checkout | Miller's Law | Break checkout into multiple simple steps. |
| Order Confirmation | Peak-End Rule | Show a success animation and friendly confirmation message. |
| Navigation | Jakob's Law | Keep navigation where users expect it (bottom navigation, search at top). |
| Primary CTA | Von Restorff Effect | Use a contrasting color for the main action button. |
| Dashboard | Common Region | Group related information inside cards. |
| Restaurant List | Continuity | Use a vertical scrolling layout for easy scanning. |
| Entire App | Prägnanz | Keep the design clean, simple, and easy to understand. |
